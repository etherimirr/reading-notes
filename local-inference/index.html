出发点

解码是在读内存

内存墙（Wulf & McKee, 1995）和 Roofline 模型（Williams & Patterson, 2009）说的是同一件事：算力增长远快于内存带宽。LLM 解码落在带宽受限的那一侧。

理论上限，实际一般只有 50–70%；不含 KV cache，长上下文时还要更多内存。示例参数：DeepSeek-V3 总 671B、激活 37B；gpt-oss-120b 约 117B、激活约 5.1B；Qwen3-30B-A3B 约 30.5B、激活约 3.3B。

MoE 改变了账本

MoE 每个 token 只读几十 B 参数，带宽压力小了；但所有专家都得放在内存里，要几百 GB。问题从"带宽不够"转成了"容量不够"。谁能便宜地提供几百 GB、带宽过得去的内存，谁就能在家跑前沿模型。

读五条线之前

先懂这几个概念

下面反复用到这些词。每个都配了小例子。

① 权重矩阵：行和列

一个线性层就是 y = W·x。x 是输入向量（比如 4,096 个数），W 是权重矩阵。每一行对应一个输出神经元，每一列对应一个输入。第 r 行第 j 列 = 第 j 个输入对第 r 个输出的系数。所以“一列”就是同一个输入 x_j 连到所有输出神经元的那一组权重。

              x₁     x₂     x₃
输出神经元 1 [ 0.30   0.30  -0.12 ]   y₁ = 0.30·x₁ + 0.30·x₂ - 0.12·x₃
输出神经元 2 [ 1.10  -0.45   0.07 ]   y₂ = 1.10·x₁ - 0.45·x₂ + 0.07·x₃
               ↑
          第 1 列 = x₁ 连到所有神经元的权重

② 权重和激活

权重是训练好就固定的参数（W）；激活是每一层的输入和输出（x、y），每来一句话都不一样。量化权重可以离线一次做完；量化激活要在推理时实时做，而且激活更容易出现极端值。常见写法：W4A16 = 权重 4 bit、激活 16 bit（权重存得小，计算前解压成 16 bit 再乘，省显存和带宽，不省计算）；W8A8 = 两者都是 8 bit（能直接用 GPU 的 INT8 乘法单元，计算也省）。

③ 量化具体怎么做

把一组数映射成少数几个整数，存整数和一个缩放系数 s。

原始值          0.12    -0.50    0.33    0.02

INT8：s = 0.50 ÷ 127 ≈ 0.0039（用最大绝对值定刻度）
除以 s 再取整     30     -127      84       5
用时乘回 s      0.118   -0.500   0.328   0.020    误差很小

INT4：s = 0.50 ÷ 7 ≈ 0.071
除以 s 再取整      2       -7       5       0
用时乘回 s      0.143   -0.500   0.357   0.000    误差变大，0.02 直接没了

实际会每 64 或 128 个数一组、每组一个 s（分组量化），组越小误差越小，但要多存一些缩放系数。

④ 为什么一个离群值能毁掉整组

原始值          0.12    -0.50    0.33    0.02    60

INT8：s = 60 ÷ 127 ≈ 0.47
除以 s 再取整      0       -1       1       0     127
用时乘回 s       0      -0.47    0.47     0      60

缩放系数由最大值决定。一个 60 把刻度撑到 0.47 一格，其他正常数全被压成 0 或 ±0.47，信息基本丢光。大模型的激活里恰好有这种离群值，后面 LLM.int8()、SmoothQuant、AWQ、QuIP# 都是在对付它。

⑤ 一阶信息、二阶信息

把损失想成一片山地，权重是你站的位置。

名字是什么对量化有什么用
一阶信息坡度（梯度）：往某个方向走一步，损失涨还是降、涨多快训练好的模型站在谷底，四周坡度都约等于 0。一阶信息说“往哪动都没影响”，对量化没用
二阶信息弯曲程度（二阶导数，写成矩阵叫 Hessian，记作 H）：谷底这个碗在各个方向上有多陡陡的方向，权重动一点损失就涨很多，要小心量化；平的方向，动很多也没关系
H 的非对角元第 j 行第 k 列：同时动第 j 和第 k 个权重时，效果是叠加还是抵消这就是“用一个权重补偿另一个权重的误差”的依据

在一层里，二阶信息很具体。如果目标是“量化后这一层的输出别变”，H 就等于 2XXᵀ，X 是校准数据经过这一层时的输入。H 的第 j 个对角元 = 输入 x_j 平时有多大（越大，它的权重出错被放大越多）；第 j 行第 k 列 = x_j 和 x_k 是否经常同时大、同时小（越相关，越能互相补偿）。所以“算二阶信息”说白了就是：用几百条样本统计一下这一层各个输入有多大、彼此有多相关。

⑥ 训练后量化和量化感知训练

训练后量化（PTQ）：模型已经训好，只用几百条校准数据决定怎么量化，不再训练。GPTQ、AWQ、SmoothQuant 都是。便宜、快，但压得越狠损失越大。量化感知训练（QAT）：训练过程中就让模型在量化后的权重上计算、适应误差，BitNet 是这一类。效果好，但要从头训或者长时间继续训，很贵。

线 ①

压缩权重：少读字节

时间工作之前卡在哪 · 做法 · 之后
2016Deep Compression（Han, Mao, Dally，ICLR 最佳论文）关键
做了　剪掉小权重，剩下的聚成 16 类共用一个值，再用哈夫曼编码
改进　AlexNet、VGG 缩小 35 到 49 倍，精度不降，能放进手机的片上内存

之前CNN 的权重用 32-bit 浮点存：AlexNet 240MB，VGG-16 552MB。手机芯片里的片上 SRAM 只有几 MB，放不下，只能每次从外部 DRAM 读权重。按论文给的 45nm 工艺数据，读一次 DRAM 约 640 pJ，读一次片上 SRAM 约 5 pJ，做一次 32-bit 浮点乘法约 3.7 pJ：耗电的是搬数据，不是计算。

做法
  1. 剪枝：把训练好的网络里绝对值小于阈值的权重直接置零，等于删掉这条连接。删完精度会掉，因为剩下的权重是按“所有连接都在”训出来的；所以接着训练剩下的权重几轮（被删的保持为零），让它们接过被删连接的活。剪、训、再剪、再训，反复几轮。AlexNet 的参数减少到约 1/9，VGG-16 约 1/13。
  2. 稀疏存储：剩下的非零权重只存值和位置。位置不存完整下标，只存“离上一个非零元素隔了几个”，这个距离通常很小，卷积层用 8 bit、全连接层用 5 bit 就够。
  3. 量化（权重共享）：每层用 k-means 把剩下的权重聚成少数几簇：卷积层 256 簇（编号 8 bit），全连接层 32 簇（编号 5 bit）。每个权重不再存自己的 32-bit 值，只存簇编号；每簇存一个中心值。之后再训练时，同一簇所有权重的梯度加在一起，用来更新这个簇的中心。
  4. 霍夫曼编码：权重大多挤在 0 附近，所以靠近 0 的几个簇编号出现得特别多。霍夫曼编码给常见编号短码、罕见编号长码，再省 20–30%。

之后AlexNet 240MB → 6.9MB（缩小 35 倍），VGG-16 552MB → 11.3MB（49 倍），精度不降，整个模型能放进片上 SRAM。留下的问题：压缩后是“稀疏 + 查表”的格式，通用 CPU、GPU 不会直接算，见下一条 EIE。

2016EIE（Han 等，ISCA）
做了　做一块专用芯片，直接在压缩后的稀疏权重上算，不用先解压
改进　不用反复读外部内存，比 GPU 快约 13 倍，能效高约 3400 倍

之前Deep Compression 压出来的是“稀疏矩阵 + 簇编号”。CPU、GPU 只会算稠密矩阵，要先解压回 32-bit 稠密矩阵再乘：存储时是小的，计算时又变大，读内存的能耗省不下来。稀疏矩阵直接在 GPU 上算也不划算，零的位置不规则，很多线程空转。

做法
  1. 直接在压缩格式上算：芯片里存的就是压缩后的权重，小到能全部放进片上 SRAM。计算时用一张 16 项的小表，把 4-bit 簇编号查成 16-bit 的真实权重值。
  2. 两种跳零：权重为零的连接根本没存，自然跳过；激活为零的输入（ReLU 之后通常一半以上是零），它对应的那一整列权重都不用读，也跳过。
  3. 并行：64 个处理单元各负责矩阵的一部分行，输入广播给所有单元，各算各的；用队列平衡各单元的工作量，避免有的忙有的闲。

之后在压缩后的全连接层上，比 GPU 快约 13 倍、能效高约 3,400 倍（比 CPU 快 189 倍、能效高约 24,000 倍）。教训：压缩要配专用硬件才能兑现收益。后来的 AI 推理芯片和软硬一体的思路，都是这条线的延续。

2022LLM.int8()（Dettmers 等，NeurIPS）
做了　找出大模型激活里少数几个离群维度，单独用 FP16 算，其余维度用 INT8
改进　175B 模型第一次用 INT8 不掉点，显存减半；缺点是速度没变快

之前大模型用 FP16 存和算，每个参数 2 字节，OPT-175B 光权重就要 350GB，要 5 张 80GB 显卡。想换成 INT8 把显存减半。小模型这样做几乎不掉点，但参数到 6.7B 以上，一量化精度就突然崩溃。

做法
  1. 找原因：大模型的激活里出现了“涌现的离群特征”：每层只有少数几个特征维度（约 0.1%），数值比其他维度大到 20 倍左右，而且几乎每个 token 都是同一批维度。就像基础概念 ④ 的例子，这些大数把缩放系数撑大，同一行里的正常数值全被压成 0。
  2. 向量级量化：不再整个矩阵共用一个缩放系数，而是激活的每一行（每个 token）一个、权重的每一列一个，粒度更细，减少互相拖累。
  3. 混合精度分解：把幅度超过 6 的那几个特征维度单独挑出来：激活的这几列和权重对应的那几行，用 FP16 相乘；其余 99.9% 的维度用 INT8 相乘；最后两个结果相加。离群维度很少，FP16 这部分的计算量可以忽略。

之后175B 模型可以用 INT8 存，显存从约 350GB 降到约 175GB，精度和 FP16 完全一样；集成进 bitsandbytes 和 Hugging Face，一个参数（load_in_8bit）就能用。留下两个问题：只到 8 bit；FP16 和 INT8 混着算，推理没有变快，小模型上甚至更慢。下一步分成两路：压到 4 bit（GPTQ）和让 INT8 真正加速（SmoothQuant）。

2023GPTQ（Frantar, Alistarh 等，ICLR）关键
做了　一列一列量化权重，每量化完一列，就把误差按二阶信息补到还没量化的列上
改进　第一次把 175B 模型压到 3 到 4 bit，一张卡几小时就能做完

之前INT8 已经能用，但想压到 4 bit 以下。最简单的做法叫 RTN：每个权重直接四舍五入到最近的格点，误差各自吞下。4 bit 时大模型困惑度明显上涨，3 bit 基本崩。更好的办法早就有：1989–1993 年的 OBD、OBS 剪枝方法，到 2022 年的 OBQ，思路都是“动一个权重后，调整其他权重把误差抵消掉”。但 OBQ 太慢，1B 以上的模型就跑不动。

做法
  1. 先懂“列”：权重矩阵的每一行是一个输出神经元，每一列是同一个输入 x_j 连到所有神经元的那组权重（见基础概念 ①）。GPTQ 一次处理一整列，也就是所有神经元在 x_j 上的那个权重同时量化。
  2. 核心直觉：用还没量化的权重补偿误差：看一个神经元 y = w₁x₁ + w₂x₂，两个权重都是 0.30，量化格点只有 0、0.5、1.0。RTN：两个都变成 0.5，系数之和从 0.6 变成 1.0，输出偏了 0.4·x。补偿法：假设校准数据里 x₁ 和 x₂ 几乎总是一样大。先把 w₁ 量化成 0.5，多了 0.2；再把 w₂ 先减 0.2 变成 0.10，然后量化成 0。系数之和 0.5，只偏 0.1·x。
  3. 补多少由二阶信息决定：如果 x₁ 和 x₂ 没关系（一个大时另一个常常是 0），减 w₂ 就补不回来，反而在 x₂ 大的样本上制造新误差。所以要先知道输入之间有多相关：用约 128 条校准数据跑一遍，记下这一层的输入 X，算出 H = 2XXᵀ，这就是这一层的二阶信息（见基础概念 ⑤）。
  4. 公式：量化第 j 列后，每一行的误差 e = w_j − q(w_j)；同一行里还没量化的第 k 个权重调整 −e × [H⁻¹]_kj ÷ [H⁻¹]_jj。和 x_j 越相关的输入，它的权重分担得越多；不相关的基本不动。所有行的输入 X 相同，H 对所有行都一样，所以所有行可以同时做。
  5. 流程：第 1 列四舍五入 → 每一行把误差按公式分摊给第 2…n 列 → 第 2 列（已经被调过）四舍五入 → 分摊给第 3…n 列 → …… 一列一列做完，进入下一层。
  6. 让它能跑 175B 的三处改动：OBQ 每一行自己挑“误差最小的先量化”，顺序各不相同，每行都要单独更新 H⁻¹，所以慢。GPTQ：所有行按同一个列顺序量化（发现顺序没那么重要），H⁻¹ 只需算一次；每 128 列一批，批内逐列量化和补偿，对批外列的更新攒着一次做，GPU 才跑得满；需要的 H⁻¹ 元素直接从 Cholesky 分解里读，不反复求逆，否则大模型上数值误差累积会算出 NaN。

之后175B 的模型在单张 A100 上约 4 小时量化到 3–4 bit，困惑度几乎不变；3-bit 的 175B 第一次能放进单张 80GB 显卡。缺点：靠几百条校准数据做优化，容易对校准集过拟合，换一个领域的任务可能掉点，后来的 AWQ 针对的就是这一点。

2023SmoothQuant（Xiao, Lin 等，Song Han 组，ICML）
做了　把激活离群通道的值除小，同时把对应权重乘大，结果不变，两边都好量化
改进　权重和激活都能用 INT8（W8A8），真正用上 INT8 乘法，约快 1.5 倍

之前LLM.int8() 只省了显存，计算还混着 FP16，没有变快。要真正用上 GPU 的 INT8 乘法单元，权重和激活都得是 INT8（W8A8）。权重好量化，分布平坦；激活难量化：某几个通道的值比其他通道大上百倍，INT8 一量化，其他通道全被压成 0（见基础概念 ④）。

做法
  1. 观察：激活的离群值总出现在固定的几个通道上，不是随机出现；权重则很平坦，没有离群值。难度全压在激活一边。
  2. 等价变换：一层计算是 Y = X·W（X 的每一列是一个输入通道，W 的每一行对应这个通道）。给 X 的第 j 列除以 s_j，同时把 W 的第 j 行乘以 s_j：(X_j ÷ s_j)·(s_j·W_j) = X_j·W_j，结果一个数都不变。
  3. 为什么有用：量化误差由每组里的最大值决定（最大值定了刻度）。激活的离群通道除以 s 后最大值降下来了；权重那一行虽然被放大，但它原来很平坦，放大一点仍然好量化。相当于把一半的量化难度从激活挪给权重。
  4. s 怎么取：s_j = max|X_j|^α ÷ max|W_j|^(1−α)，α 取 0.5 时两边的最大值被拉到同一量级。例：某通道激活最大 100、权重最大 1，s = 10，之后激活最大 10、权重最大 10，两边都能用 INT8 表示。
  5. 零开销：s 用校准数据离线算好。激活除以 s 这一步合并进前一层（LayerNorm）的参数里，权重乘 s 直接存进权重。推理时没有任何额外计算。

之后OPT-175B、BLOOM-176B、530B 的 MT-NLG 都做到 W8A8，精度几乎不降；用上 INT8 矩阵乘，最高约 1.56 倍加速、显存减半。留下的问题：8 bit 对本地推理还不够小。本地单用户时瓶颈是读权重，更需要把权重压到 4 bit（W4A16），见 AWQ。

2023–24AWQ（Lin 等，Song Han 组，MLSys 2024 最佳论文）关键
做了　按激活大小找出约 1% 的重要通道，放大它们的权重再量化，让误差变小
改进　做到权重 4 bit、激活 16 bit（W4A16），不用混合精度，也不去拟合校准数据，换领域也稳，成为标准 4-bit 方案

之前本地单用户推理时，瓶颈是读权重的带宽，最想要的是权重 4 bit、激活保持 16 bit（W4A16）。GPTQ 能做到，但它在校准数据上做二阶优化，容易过拟合，换领域（指令模型、代码、多模态）可能掉点。另一个直觉做法是把重要权重保留 FP16、其余 4 bit，但混合精度在硬件上很难高效实现。

做法
  1. 观察：权重不是同等重要：只把约 1% 的“显著”通道保留成 FP16，4 bit 的困惑度就几乎回到原模型。关键是怎么选：要看对应激活的幅度。激活大的输入通道，它的权重一旦出错会被放大，所以重要。只按权重自身大小选，效果和随机选差不多。
  2. 不用混合精度，改用缩放：给显著通道的权重乘一个大于 1 的系数 s 再量化，对应激活除以 s（和 SmoothQuant 同样的等价变换）。为什么误差变小：量化误差的绝对大小由组内最大值决定的步长决定，放大一个通道通常不改变组的最大值，步长不变；这个通道的权重变大了，乘回激活时误差再被除以 s，所以这个通道的误差缩小到约 1/s。
  3. s 怎么定：s = 激活平均幅度的 α 次方，α 在 0 到 1 之间取 20 个值网格搜索，选让这一层输出误差最小的。只做前向、不做反向传播，也不针对校准数据去拟合权重本身，所以不容易过拟合。
  4. 格式：全部权重统一 INT4，每 128 个一组共享缩放系数，没有混合精度，硬件好加速。配套推理框架 TinyChat 把反量化和矩阵乘融合在同一个计算核里。

之后Llama 系列 4 bit 精度接近 FP16，跨领域稳定；TinyChat 在桌面 4090 和 Jetson Orin 上比 Hugging Face FP16 快 3 倍以上。成为 vLLM、TensorRT-LLM、Hugging Face 的标准 4-bit 方案之一。留下的问题：低于 4 bit 时，这种按通道缩放不够用了，见 QuIP#、AQLM。

2023QLoRA（Dettmers 等，NeurIPS）
做了　底座模型压成 4-bit NF4 后冻结，只训练外挂的 LoRA 小矩阵
改进　65B 模型在一张 48GB 显卡上就能微调，效果接近 16-bit 全量微调

之前全量微调 65B 模型，要存 16-bit 权重（130GB）、梯度和 Adam 优化器的两份状态，总共 780GB 以上显存，十几张 80GB 卡。LoRA 冻结原权重、只训两个小矩阵，省掉了大部分梯度和优化器状态；但冻结的权重本身还是 16 bit，65B 仍要 130GB，一张卡放不下。

做法
  1. 底座存成 4 bit 的 NF4：预训练权重近似正态分布。NF4 的 16 个取值按正态分布的分位数来定：中间密、两头疏，每个取值覆盖同样多的权重，信息损失最小。每 64 个权重一组共享缩放系数。计算时把权重解压回 BF16 再乘。
  2. 只训练 LoRA：在每个线性层旁边加两个小矩阵 A（d × r）和 B（r × d），r 远小于 d；输出 = 冻结层的输出 + B·A·x。梯度只更新 A、B，它们用 BF16。
  3. 双重量化：每组 64 个权重要存一个 32-bit 缩放系数，平均每个参数多 0.5 bit。把这些系数本身再量化成 8 bit（每 256 个一组），降到约 0.127 bit，每个参数省约 0.37 bit，65B 模型省约 3GB。
  4. 分页优化器：长序列时显存会出现瞬时峰值导致溢出。用 NVIDIA 统一内存，显存不够时自动把优化器状态换到 CPU 内存，用时再换回来。

之后一张 48GB 显卡就能微调 65B；训出的 Guanaco 在 Vicuna 基准上达到 ChatGPT 的约 99.3%。NF4 后来也成了本地加载大模型的常用格式。

2023–24QuIP#（ICML 2024）、AQLM（ICML 2024）
做了　不再逐个数地量化，改成几个数一组，去码本里查最接近的向量；QuIP# 还会先随机旋转，把离群值摊平
改进　压到 2 bit 也基本能用，以前到 2 bit 模型就崩了

之前4 bit 已经成熟。再往下到 2 bit，每个权重只能取 4 个值：格点太粗，再加上少数大值把刻度撑大，误差大到模型不可用。

做法
  1. 不相干处理（先旋转）：给权重矩阵左右各乘一个随机正交矩阵（QuIP# 用随机 Hadamard 变换，计算很快）。正交变换可以在推理时对输入、输出反变换回来，不改变结果；但它把少数大值“打散”到所有元素上，整个矩阵变得均匀、接近高斯分布，没有离群值了。
  2. 向量量化（QuIP#）：不再一个权重一个权重地找格点，而是 8 个权重一组，从码本里找最接近的 8 维向量，只存编号。码本来自 E8 格点，它是 8 维空间里最紧密的排列方式，旋转后接近高斯的权重落在它附近误差最小。2 bit × 8 = 16 bit 编号，对应 65,536 个向量，但 E8 有对称结构，只需存很小一部分。
  3. 微调：量化完再用少量数据微调没有量化的部分（如 LayerNorm），把精度补一些回来。
  4. AQLM（另一条路）：每组 8 个权重表示成几个码本向量之和（加性量化），码本和每组的编号交替优化，再逐层微调。

之后2-bit 的大模型第一次基本可用（如 Llama 2 70B），在 2–3 bit 区间达到当时最好的精度和体积折中。代价：推理时要查码本，计算核复杂，速度不如 INT4。

2024–25BitNet b1.58（2024-02）→ BitNet b1.58 2B4T（2025-04）
做了　从头训练时就规定权重只能取 −1、0、+1
改进　每个权重约 1.58 bit，乘法变成加减法，3B 以上精度接近 FP16；代价是必须从头训练

之前前面都是训练后量化：模型先用 16 bit 训好再压，压得越狠损失越大，2 bit 已是极限。而且权重就算是 4 bit，计算时还是要解压做乘法。

做法
  1. 从训练开始就量化：训练时保存一份高精度的“影子权重”用来更新；每次前向计算前，把它除以整个矩阵的平均绝对值，四舍五入，截断到 {−1, 0, 1}。
  2. 直通估计：四舍五入的导数几乎处处为零，梯度传不过去。反向传播时假装取整是恒等函数，梯度直接加到影子权重上。
  3. 激活用 8 bit：每个 token 按自己的最大绝对值缩放到 8 bit。
  4. 为什么叫 1.58 bit：三个取值，log₂3 ≈ 1.58。比纯 1 bit（只有 ±1）多一个 0，可以表示“这条连接没用”，相当于自带剪枝。
  5. 乘法变加法：权重只有 −1、0、1，矩阵乘就变成把对应激活加上、减去或跳过。

之后3B 规模起和同大小的 FP16 LLaMA 困惑度持平，显存约 1/3.5、延迟快约 2.7 倍。BitNet b1.58 2B4T 是用 4 万亿 token 训练的 2B 开源模型，配 bitnet.cpp 在普通 CPU 上高效运行。缺点：必须从头训练，不能把现成模型转过来；几十 B 以上的规模还没有被充分验证。

2023–25MXFP4 / NVFP4；gpt-oss 以 MXFP4 发布（2025-08）
做了　定义硬件原生的 4-bit 浮点格式，每 32 个（MX）或 16 个（NV）数共享一个缩放系数
改进　4 bit 不再只是软件技巧，芯片可以直接计算；gpt-oss-120b 一张 80GB 显卡就放得下

之前4 bit 一直是软件层面的技巧：INT4 权重存在显存里，计算前要先解压成 FP16 再进 Tensor Core（W4A16）。省了显存和带宽，没省计算。而且整数格点是均匀的，不够贴合“中间密、两头疏”的权重分布。

做法
  1. 4-bit 浮点 E2M1：1 位符号、2 位指数、1 位尾数，只能表示 ±{0, 0.5, 1, 1.5, 2, 3, 4, 6}。靠近 0 密、远处疏，比 INT4 更贴合权重分布。
  2. 块缩放：4 bit 自己的范围太小，所以每一小块共享一个缩放系数。MXFP4（OCP 标准）：每 32 个元素共享一个 8-bit 的 2 的幂缩放。NVFP4（NVIDIA Blackwell）：每 16 个元素共享一个 FP8 缩放，再乘一个整张量的缩放，更精细、误差更小。
  3. 硬件原生：Blackwell 的 Tensor Core 直接吃 FP4 做矩阵乘，不用先解压，吞吐是 FP8 的 2 倍。
  4. 官方模型直接用：OpenAI 的 gpt-oss 把 MoE 专家权重以 MXFP4 格式发布。

之后gpt-oss-120b 能放进单张 80GB 显卡，gpt-oss-20b 能在 16GB 内存的机器上跑。4-bit 浮点从社区技巧变成了硬件和官方模型的标准。

2026RFID-MoE（ICML 2026）等 MoE 专家级压缩
做了　按每个专家的使用频率和信息量分配压缩预算，常用的、信息多的少压
改进　Qwen3-30B 压掉 60% 时，困惑度比之前的方法低 8 以上

之前MoE 模型（如 Qwen3-30B）总参数大，本地放不下，需要压缩。常用办法是对每个专家的权重矩阵做 SVD 低秩分解，只保留最主要的 r 个方向。之前的方法给所有专家分一样的秩，或者只看权重本身。但有的专家几乎每个 token 都会被选中，有的很少用；有的专家权重信息量大、难压，有的很好压。

做法
  1. 给专家打分：路由频率（校准数据里被选中的比例）× 有效秩（信息分散在多少个方向上）。
  2. 按分数分预算：总秩预算固定，分数高的专家组多分秩，不常用、信息少的压得更狠。
  3. 补回残差：SVD 丢掉的部分不直接扔，用一个参数很少的稀疏投影近似补回来。

之后Qwen3-30B 压缩 60% 时，PTB 困惑度 16.92，比 MoBE、D2-MoE 低 8 以上；HellaSwag 零样本高约 8%。和后面 KTransformers 按使用频率决定专家放哪里，是同一个思路：专家不平等。

走向：事后量化 → 量化感知训练、原生低比特训练 → 硬件原生支持 4-bit 浮点

线 ②

KV cache 与注意力：长上下文的内存大头

时间工作之前卡在哪 · 做法 · 之后
2019MQA（Shazeer，One Write-Head is All You Need）

之前生成每个新 token 时，都要读之前所有 token 的 Key 和 Value（KV cache），每个注意力头各存一份。以 32 层、32 个头、每头 128 维、FP16 的 7B 模型为例，每个 token 的 KV 要 32 × 32 × 128 × 2（K 和 V）× 2 字节 = 512KB，4k 上下文就是 2GB。批量一大，KV 比模型权重还大，解码时间都花在读它上。

做法
  1. 只保留一组 K、V：所有 query 头共享同一个 K 头和 V 头，Q 仍然是多头。
  2. 为什么还能工作：不同头主要在“问什么”（Q）上不同；K、V 是被查询的内容，共享一份损失有限。

之后KV cache 缩小到 1/头数（上例从每 token 512KB 降到 16KB），解码大幅变快；代价是质量略降、训练不太稳定。PaLM、Falcon 采用。折中方案见 GQA。

2022FlashAttention（Dao 等，NeurIPS）关键

之前标准注意力分三步：先算 S = QKᵀ（N × N 矩阵）写进显存；再读回来做 softmax 得到 P，又写回显存；最后读 P 乘 V。序列长 8k 时，每个头的 N × N 矩阵就有 6,400 万个数。GPU 计算很快，但显存读写慢，时间主要花在搬这个大矩阵上；显存占用随 N² 增长，长序列放不下。

做法
  1. 分块：把 Q、K、V 切成小块，每次只把一块 Q 和一块 K、V 搬进片上 SRAM（每个计算单元约 100–200KB），在 SRAM 里算这一小块的注意力分数。
  2. 在线 softmax：softmax 需要整行的最大值和总和，但一次只看到一块。办法是边算边更新：记住当前看到的最大值和分母；新的一块里如果出现更大的值，就把之前累加的结果乘一个修正系数（e 的“旧最大值 − 新最大值”次方），再加上新块的贡献。所有块看完，结果和一次算整行完全相同。
  3. 从不写回 N × N 矩阵：每一块算完立刻乘 V、累加到输出，中间的分数只存在于 SRAM 里。
  4. 反向传播时重算：训练反向需要 P，但不存它，反向时用保存的最大值和分母重新算一遍。多算一点，省掉大量显存读写，反而更快。

之后注意力的额外显存从 O(N²) 降到 O(N)，结果精确，不是近似；GPT-2 训练约 3 倍快，16k、64k 的长上下文能训练了。FA-2（2023）调整循环顺序和线程分工，再快约 2 倍；FA-3（2024）用上 Hopper 的异步搬运和 FP8，H100 利用率约 75%。启示：按内存层级重新安排计算，比减少计算量更重要，这也是本地推理的核心思路。

2022Orca（Yu 等，OSDI）

之前推理服务以“请求”为单位组批：一批 8 个请求一起生成，要等最长的那个生成完，整批才结束、换下一批。短请求早早写完，位置空着；新来的请求要排队等整批结束，延迟高，GPU 利用率低。

做法
  1. 迭代级调度：每生成一个 token（一次迭代）就重新组一次批：生成完的请求立刻移出，排队的新请求立刻补进来。
  2. 选择性批处理：不同请求长度不同，注意力没法拼成一个矩阵，就按请求分开算；线性层和 FFN 不在乎长度，把所有请求的 token 拼在一起算。

之后同等延迟下，GPT-3 175B 的吞吐比 FasterTransformer 高约 37 倍。“连续批处理”成为 vLLM、TGI、TensorRT-LLM 等所有推理服务的标配。留下的问题：KV cache 的显存怎么管，见 vLLM。

2023vLLM / PagedAttention（Kwon 等，SOSP）关键

之前每个请求的 KV cache 要在显存里占一段连续空间。不知道最终会生成多长，只能按最大长度（如 2,048 个 token）预留；实际平均只用到一部分，加上碎片，60–80% 的 KV 显存浪费掉。显存被占满，一批放不下几个请求，吞吐上不去。

做法
  1. 分页：像操作系统的虚拟内存，把 KV cache 切成固定大小的块（每块 16 个 token），生成到哪里分配到哪里，不用预留。
  2. 块表：每个请求一张表，记录“第几个逻辑块放在显存的哪个物理块”。物理块可以不连续。
  3. PagedAttention 计算核：算注意力时按块表把分散的 K、V 块读进来，对模型完全透明。
  4. 共享和写时复制：多个请求有相同前缀（同一个系统提示，或者一次采样多个回答）时，前缀的块只存一份、记引用次数；某个请求要往共享块里写新内容时才复制一份。

之后KV 显存浪费降到 4% 以下，同样显存能放 2–4 倍的请求；吞吐比 Hugging Face Transformers 高 14–24 倍，比 TGI 高 2.2–3.5 倍。vLLM 成为最流行的开源推理引擎。

2023GQA（Ainslie 等，EMNLP）

之前多头注意力（MHA）质量好，但 KV 大；MQA 省内存，但质量掉、训练不稳。

做法
  1. 分组共享：把 query 头分成 G 组，每组共享一对 K、V。G = 1 就是 MQA，G = 头数就是 MHA。比如 Llama 2 70B：64 个 query 头、8 组 K/V，KV cache 缩小到 1/8。
  2. 升级已有模型：把原来同一组里几个头的 K、V 投影矩阵取平均合成一个，再用原训练约 5% 的算力继续训练，恢复质量。

之后质量接近 MHA、速度接近 MQA。Llama 2 70B、Llama 3、Mistral 都用 GQA，它成了新模型的默认配置。

2023H2O（Zhang 等，NeurIPS）

之前长对话里 KV cache 随长度线性增长，最终显存放不下。最简单的办法是只保留最近的 token（滑动窗口），但会丢掉前面的关键信息，质量掉得很厉害。

做法
  1. 观察：把每个 token 从后面所有 token 那里收到的注意力加起来，分布非常不均：少数“重击者”token 拿走了大部分注意力，而且它们往往是文本里经常一起出现的关键词。
  2. 驱逐策略：KV 预算固定（如原来的 20%）：保留最近的一批 token 加上累计注意力最高的一批。每生成一个新 token 就更新累计分数，把分数最低的逐出。

之后只留 20% 的 KV，多数任务质量接近完整版，吞吐比当时的主流卸载方案高最多约 29 倍。留下的问题：逐出的信息找不回来，需要精确回忆前文的任务会失败。

2023 → ICLR 2024StreamingLLM（Xiao 等，Song Han 组）

之前想让模型无限长地对话，最省的办法是滑动窗口：只留最近 L 个 token 的 KV。但实测一旦开头的 token 被挤出窗口，困惑度立刻飙升，模型开始输出乱码。

做法
  1. 发现注意力汇点：不管内容是什么，开头几个 token 都会吸收大量注意力，在很多层、很多头里超过一半。
  2. 解释：softmax 要求每一行的注意力加起来等于 1。当前 token 没什么需要关注的时候，多余的注意力也得放到某处；开头的 token 对所有后续 token 都可见，于是被训练成了“垃圾桶”。窗口丢掉它们以后，多余的注意力无处可放，整个分布被打乱。
  3. 做法：永远保留最前面 4 个 token 的 KV（汇点），再加最近 L 个 token 的滑动窗口；位置编码按缓存里的位置重新编号。
  4. 更进一步：预训练时专门加一个可学习的“汇点 token”，只要 1 个就够。

之后不微调、不重算，Llama 2、MPT、Falcon、Pythia 都能稳定生成 400 万 token 以上，比“滑动窗口 + 重算”快最多约 22 倍。注意：它解决的是“不崩溃”，不是“全记住”，窗口外的内容还是会忘。

2024KIVI（ICML）、KVQuant（NeurIPS）

之前权重已经压到 4 bit，KV cache 还是 16 bit。长上下文、大批量时，KV 反而成了显存和带宽的大头（比如上面 7B 模型 4k 上下文，每个请求 2GB）。

做法
  1. K 和 V 的分布不同：K 的离群值集中在固定的几个通道上（和激活的离群通道类似）；V 没有明显的通道离群，但每个 token 的误差会直接混进输出。
  2. KIVI：K 按通道量化（每个通道一个缩放，离群通道单独处理），V 按 token 量化，都压到 2 bit。最近几十个 token 先用全精度存在一个小缓冲区，攒够一组再量化。不用校准、不用调参。
  3. KVQuant：K 在加旋转位置编码（RoPE）之前量化，因为 RoPE 会把通道两两旋转混在一起，破坏通道规律；量化点不均匀（按敏感度加权的 k-means）；每个向量里最大的约 1% 单独用稀疏格式存全精度。

之后KIVI 在 2 bit 时显存减少约 2.6 倍、批量可加大 4 倍、吞吐提升 2.35–3.47 倍。KVQuant 3 bit 时困惑度损失小于 0.1，LLaMA-7B 在单张 A100 上支持 100 万 token 上下文（8 张卡 1,000 万）。

2024-05MLA（DeepSeek-V2）

之前GQA 之后，每层仍然要为每个 token 存好几组完整的 K 和 V（如 8 组 × 128 维 × 2）。再减少组数又会掉质量。

做法
  1. 低秩联合压缩：每个 token 的隐藏状态先乘一个下投影矩阵，得到一个很小的潜向量 c（512 维），缓存里只存 c。需要 K、V 时，再用上投影矩阵把 c 还原成每个头的 K 和 V。
  2. 吸收技巧：推理时其实不用真的还原 K：注意力分数 q·k = q·(W·c) = (Wᵀq)·c，可以把上投影矩阵并进 query 这边，直接拿 c 算分数；V 的上投影同理并进输出投影。所以缓存小了，计算也没变多。
  3. 位置编码解耦：RoPE 会随位置旋转 K，破坏上面的合并技巧。所以额外拿出一小块维度（64 维）专门带 RoPE、单独缓存，其余部分不加位置编码。

之后每个 token 只缓存约 576 个数（512 + 64），KV cache 比标准多头注意力减少约 93%；DeepSeek-V2 的生成吞吐是 DeepSeek 67B 的 5.76 倍，效果还略好于 MHA。DeepSeek-V3、R1 继续使用。

2024–25混合注意力：Jamba、MiniMax-01、Qwen3-Next、Kimi Linear

之前只要用标准 softmax 注意力，KV cache 就随长度线性增长，每生成一个 token 都要读全部历史。上下文到百万 token 时，KV 要几十 GB，速度也越来越慢。

做法
  1. 线性注意力、状态空间层：不存每个 token 的 K、V，而是维护一个固定大小的“记忆矩阵”（状态），每来一个 token 更新一次。状态大小和长度无关，显存和每步计算都是常数。代价：固定大小的状态记不住所有细节，精确回忆（比如“第 3 段第 2 句是什么”）会变差。
  2. 混合：大部分层用线性层，每隔几层保留一层标准注意力负责精确回忆。
  3. 更新规则的改进：DeltaNet 一类方法更新状态时先删掉旧的对应内容再写入新的（delta 规则），而不是一直累加，让固定大小的状态记得更准。
  4. 代表：Jamba（2024-03）Transformer 和 Mamba 1:7，加 MoE；MiniMax-01（2025-01）线性注意力和 softmax 注意力 7:1，456B MoE；Qwen3-Next（2025-09）Gated DeltaNet 和门控注意力 3:1，加 80B 总 / 约 3B 激活的超稀疏 MoE；Kimi Linear（2025-10）Kimi Delta Attention 和 MLA 3:1。

之后Kimi Linear 报告 KV cache 减少约 75%、百万 token 上下文时解码吞吐最高约 6 倍；MiniMax-01 推理时支持约 400 万 token；Jamba 单张 80GB 卡能跑约 14 万 token。长上下文开始能在本地机器上跑。

走向：先省带宽（FlashAttention）→ 再省容量（分页、量化、低秩）→ 从模型结构上去掉 KV cache

线 ③

并行解码：读一次权重，多出几个 token

时间工作之前卡在哪 · 做法 · 之后
2022–23投机解码（Leviathan 等，ICML 2023；DeepMind 的 Chen 等同期）关键

之前自回归解码每一步都要把（激活的）全部权重从内存读一遍，却只产出 1 个 token。本地单用户时，GPU 的计算单元大部分时间在等数据，算力闲着。

做法
  1. 草稿：用一个小模型（比如同家族的 1B 模型）快速连续猜 γ 个 token（比如 4 个）。小模型便宜，几乎不花时间。
  2. 一次验证：把这 γ 个草稿 token 一起送进大模型跑一次前向。因为是并行的，读一次权重就能同时算出这 γ + 1 个位置上大模型的概率，成本和生成 1 个 token 差不多。
  3. 接受规则：从第一个草稿开始逐个检查：大模型给它的概率是 p、小模型是 q，以 min(1, p ÷ q) 的概率接受。一旦拒绝，就从修正分布 max(0, p − q)（归一化后）里重新采样一个 token，后面的草稿全部作废。
  4. 为什么不损失质量：可以严格证明，按这个规则，最终每个 token 的分布和大模型自己一个个生成完全相同。猜对就白赚，猜错只浪费一点小模型的计算。

之后T5-XXL 约 2–3 倍加速，Chinchilla 70B 约 2–2.5 倍，输出质量零损失。前提：要有一个分布接近、又足够快的小模型。后面 Medusa、EAGLE 就是为了去掉这个独立小模型。

2024Medusa（ICML）

之前投机解码需要一个和大模型同一个分词器、分布接近的小草稿模型。很多模型家族没有现成的，单独训练和部署两个模型也麻烦。

做法
  1. 多个预测头：在大模型最后一层的隐藏状态上加几个小的前馈头。原本的输出头预测下一个 token，第 k 个 Medusa 头预测再往后第 k + 1 个 token。
  2. 候选树：每个头取前几个候选，组合成一棵候选树（比如头 1 的前 3 个 × 头 2 的前 2 个……）。
  3. 树形注意力：把整棵树展平成一个序列，用一个特殊的注意力掩码让每个候选只看到自己这条路径上的前驱，一次前向就验证所有路径，选接受得最长的那条。
  4. 训练：Medusa-1 冻结大模型、只训新加的头，几个小时；Medusa-2 和大模型一起训，接受率更高。

之后约 2.2–3.6 倍加速。缺点：每个头只看当前的隐藏状态，就直接猜后面第 2、3、4 个 token，不知道前面猜了什么，越往后越不准，见 EAGLE。

2024–25EAGLE（ICML 2024）→ EAGLE-2（EMNLP 2024）→ EAGLE-3（2025）

之前Medusa 的头直接从当前隐藏状态猜后面几个 token，看不到前面的草稿选了哪个，后面的接受率很低。

做法
  1. 在特征层预测（EAGLE）：草稿模型不直接预测 token，而是预测大模型倒数第二层的隐藏状态（特征），再用大模型自己的输出头把特征变成 token。特征比 token 更平滑、更好预测。
  2. 把已采样的 token 喂回去：草稿每一步的输入 = 上一步的特征 + 实际采样出来的那个 token。这样它知道自己走的是哪条分支，消除“特征一样、但下一个 token 不同”的不确定性。
  3. 草稿模型很轻：只有一层 Transformer，可以自回归地连猜好几步。
  4. EAGLE-2：用草稿模型自己的置信度估计接受率，动态扩展最可能的分支，草稿树的形状随上下文变化。
  5. EAGLE-3：不再强制预测特征（这个约束让加更多训练数据也没用），改为直接预测 token；输入融合大模型低、中、高三层的特征；训练时就模拟推理时的多步草稿。

之后EAGLE 约 3 倍加速，EAGLE-2 约 3–4 倍，EAGLE-3 最高约 6.5 倍。已被 vLLM、SGLang 等主流推理引擎集成。

2024-12MTP（DeepSeek-V3）

之前草稿头都是模型训练好以后再加的，和主模型的配合有限；而且预训练时每个位置只学“下一个 token”，学习信号稀疏。

做法
  1. 训练时多预测一个：主模型后面串一个 MTP 模块（一层 Transformer，和主模型共享词嵌入和输出头），输入主模型的隐藏状态和下一个 token 的嵌入，预测再下一个 token。它的损失以较小的权重加进总损失。
  2. 好处一：每个位置多一份学习信号，让模型提前“规划”后面的内容。
  3. 好处二：推理时这个模块直接当投机解码的草稿，猜第二个 token，由主模型验证。

之后第二个 token 的接受率 85–90%，每步平均出约 1.8 个 token，生成约 1.8 倍快。DeepSeek-V3、R1 和之后多个模型采用。

2025扩散语言模型：LLaDA、Mercury、Gemini Diffusion

之前上面所有方法都还在自回归框架里：token 本质上仍是从左到右一个个确定，加速靠“猜得准”。

做法
  1. 掩码扩散训练：随机把一段文本的一部分（比例从 0 到 100% 随机）换成掩码，让模型同时预测所有被掩的位置。
  2. 生成：从一整段全是掩码的序列开始；每一步同时预测所有掩码位置，把最有把握的一批揭开，其余继续掩着；重复几十步，整段生成完。
  3. 为什么可能更快：每一步并行确定很多个 token，总步数可以远少于 token 数，读一次权重换来多个 token。
  4. 代表：LLaDA（2025-02，8B，从头训练的掩码扩散模型）；Inception Labs 的 Mercury（2025-02，商用，代码生成）；Google 的 Gemini Diffusion（2025-05，实验性）。

之后LLaDA 8B 和 LLaMA3 8B 水平相当；Mercury 报告在 H100 上超过 1,000 token/s。问题：质量和长文本能力还在追赶自回归模型，KV cache 这类成熟优化不能直接套用。

为什么对本地特别重要：本地是单用户、小批量，算力大量闲置。投机解码把闲置的算力换成速度

线 ④

分层存放、按需搬运：容量不够怎么办

时间工作之前卡在哪 · 做法 · 之后
2023FlexGen（Sheng 等，ICML）

之前模型放不进显存就跑不了，只能买多张卡。很多离线任务（批量处理文档、跑基准测试）不在乎单条延迟、只在乎总吞吐，也被显存卡住。

做法
  1. 三层存储：权重、激活、KV cache 可以分别放在 GPU 显存、CPU 内存、磁盘上，每一部分各放多少比例可调。
  2. 搜索最优方案：建一个成本模型（每层的计算时间、各层存储之间的搬运带宽），用线性规划搜出在给定硬件上吞吐最高的放置比例。
  3. 之字形调度：常规做法是一个批次从第 1 层算到最后一层，每层权重都要搬一次。FlexGen 反过来：把一层的权重搬进来，连续处理很多个批次之后再换下一层，一次搬运摊到很多批次上。
  4. 压缩：权重和 KV 再用分组量化压到 4 bit，减少搬运量。

之后一张 16GB 的 T4 能跑 OPT-175B，约 1 token/s（有效批量很大），吞吐比其他卸载方案高最多约 100 倍。只适合离线批处理：单条请求的延迟很高，对话用不了。

2023Deja Vu（Liu 等，ICML）

之前每个 token 都把全部注意力头和全部 MLP 神经元算一遍，但对某个具体输入，真正起作用的只是一小部分。传统剪枝是“静态稀疏”，对所有输入删同样的部分，删多了质量就掉。

做法
  1. 上下文稀疏：对具体输入，只有一小部分 MLP 神经元和注意力头对输出有明显影响；而且哪些有用取决于输入，换一个输入就换一批。
  2. 提前预测：在第 l 层计算的同时，用一个很小的 MLP 预测器看当前的激活，预测第 l + 1 层要用哪些头和神经元。相邻层的隐藏状态很相似，所以能提前猜。
  3. 只算选中的：第 l + 1 层只读、只算选中的那部分权重；预测和计算并行，不增加延迟。

之后OPT-175B 推理延迟比 FasterTransformer 降低 2 倍以上，质量不降。意义：后面 PowerInfer、LLM in a flash 的“只搬运会用到的权重”从这里来。限制：依赖 ReLU 这类会产生大量零的激活函数，现在流行的 SwiGLU 稀疏性弱得多。

2023-12 → ACL 2024LLM in a flash（Alizadeh 等，Apple）关键

之前手机、笔记本的内存只有 8–16GB，7B 模型 FP16 就要 14GB，放不下。闪存（SSD）有几百 GB，够大，但带宽只有内存的几十分之一，而且小块随机读特别慢（每次读都有固定延迟）。朴素地每个 token 从闪存把需要的权重读一遍，一个 token 要好几秒。

做法
  1. 只加载会激活的神经元：FFN 用 ReLU 时，每个 token 超过 90% 的神经元输出为零。用一个低秩预测器提前猜哪些神经元会激活，只从闪存读这些神经元对应的权重。模型要先 ReLU 化：把原来的激活函数换成 ReLU 再微调。
  2. 窗口化：把最近 5 个 token 用过的神经元留在内存里；新 token 进来时，只读“新激活、还不在内存里”的那部分，删掉窗口外不再用的。相邻 token 激活的神经元高度重叠，每次只需读很少的增量。
  3. 行列打包：一个 FFN 神经元对应上投影矩阵的一列和下投影矩阵的一行，它们总是一起被用到。把它们挨着存，一次读一块两倍大的连续数据，延迟几乎不变；闪存的连续读比随机读快得多。
  4. 内存管理：预先分配固定的内存块，新神经元直接覆盖被删的位置，避免反复申请和拷贝。

之后能跑约为内存两倍大的模型；比朴素按需加载，CPU 上快 4–5 倍、GPU 上快 20–25 倍。第一次系统地把闪存当作权重存储做到可用，后来端侧推理、MoE 专家放闪存的工作都从这里出发。

2023-12 → SOSP 2024PowerInfer（Song 等，上交 IPADS）→ PowerInfer-2（2024-06）

之前消费级显卡只有 24GB 显存，放不下 40B 以上的模型；全放 CPU 内存又太慢，CPU 的算力和带宽都低。llama.cpp 的做法是按层切：前几层放 GPU、后几层放 CPU，但 CPU 那部分拖慢了整体。

做法
  1. 观察幂律：离线跑大量数据，统计每个神经元被激活的频率，发现极不均匀：少数“热神经元”几乎对所有输入都激活，大量“冷神经元”只在特定输入上才激活。
  2. 按神经元切，不按层切：热神经元的权重预先放 GPU；冷神经元放 CPU 内存，而且直接在 CPU 上算，不搬到 GPU。两边各算各的，最后合并结果。
  3. 在线预测：每层用一个小预测器猜当前 token 会激活哪些神经元，只算这些（同样利用 ReLU 稀疏性）。
  4. 稀疏计算核：专门写了按神经元粒度跳过计算的 GPU 和 CPU 计算核。
  5. PowerInfer-2：搬到手机：按神经元簇调度，同时用手机的 NPU 和 CPU，并和 UFS 闪存读取做成流水线。

之后单张 RTX 4090 上平均约 13 token/s（OPT-175B 等模型，最高约 29），比 llama.cpp 快最高约 11.7 倍，只比服务器级 A100 低约 18%。PowerInfer-2 能在手机上跑 47B 的 Mixtral，约 11 token/s。

2023-12Mixtral 卸载（Eliseev & Mazur）

之前Mixtral-8x7B 总参数约 47B，4 bit 也要 20 多 GB，放不进 16GB 的 T4 或 12GB 的 RTX 3060。但它每层 8 个专家里，每个 token 只用 2 个，大部分专家在任意时刻都闲着。

做法
  1. LRU 专家缓存：每层只在 GPU 上缓存最近用过的几个专家，其余放 CPU 内存。用到不在缓存里的专家时才从 CPU 搬过来，替换掉最久没用的那个。相邻 token 经常用同一批专家，命中率不低。
  2. 推测预取：路由器很简单，可以拿当前层的隐藏状态喂给下一层的路由器，提前猜下一层会用哪些专家，提前开始搬运，把搬运时间藏在计算后面。
  3. 混合量化：注意力层压到 4 bit，专家压到 2–3 bit；专家占了参数的绝大部分，压它最划算。

之后在 Colab 免费的 T4 或 RTX 3060 上，Mixtral-8x7B 能以每秒 2–3 个 token 的交互速度运行。第一次针对 MoE 结构做卸载，后面的 KTransformers 等都沿着这条路走。

2025KTransformers（Chen 等，清华 MADSys，SOSP）关键

之前DeepSeek-V3/R1 有 671B 参数，4 bit 也要约 340GB，任何消费级显卡都放不下。通用的卸载方案（如 llama.cpp）没有针对 MoE 结构：要么大量参数放 CPU，CPU 算得慢拖累整体；要么频繁在 CPU 和 GPU 之间搬专家，PCIe 带宽成了瓶颈；CPU 和 GPU 还常常互相等待。

做法
  1. 按结构切分：每个 token 都要用的部分（MLA 注意力、KV cache、共享专家，二十多 B 参数）放 GPU；256 个路由专家（每个 token 只激活其中 8 个，合计约 654B 参数）放 CPU 内存，并且就在 CPU 上算，不搬到 GPU。
  2. 让 CPU 算得快：用 Intel AMX（CPU 里的矩阵运算单元）和 AVX-512 写专门的专家计算核，按专家批量处理，让 CPU 计算接近内存带宽的上限。
  3. 异步调度和 CUDA Graph：CPU 和 GPU 的任务通过异步队列衔接；GPU 那边用 CUDA Graph 把一串操作录成一张图一次提交，减少逐个启动的开销。
  4. Expert Deferral（专家延迟）：正常情况下第 l 层的专家全部算完，GPU 才能开始第 l + 1 层，两边互相等。KTransformers 让一部分专家的结果推迟一层再合并进残差流：GPU 算第 l + 1 层的注意力时，CPU 还在算第 l 层剩下的专家，两边重叠起来。作者测过，这对输出质量影响很小。

之后一张 16GB 的 RTX 4080 加一台大内存服务器，就能跑 671B 的 DeepSeek，吞吐比之前方案高 1.66–19.74 倍。2026 年已扩展到 FP8 精度跑 DeepSeek-V3、Qwen3.5-397B，是“在家跑前沿 MoE”的代表方案。

2026DALI、FlashMoE、MoE-CORE、FineMoE（EuroSys '26）等

之前KTransformers 依赖一台有几百 GB 内存的服务器。普通 PC 和手机的内存放不下全部专家，只能放到闪存；专家在 GPU、内存、闪存之间怎么放、什么时候预取、缓存满了先扔谁，之前大多沿用通用的 LRU 策略。

做法
  1. DALI（2026-02）：根据实际工作负载决定哪些专家放 GPU、哪些放 CPU，并让 CPU 和 GPU 都参与计算，面向本地 PC。
  2. FlashMoE（2026-01，KAIST）：专家直接从闪存读；分析证明 LRU、LFU 这类通用缓存策略对专家的路由模式天生不合适，设计了专门的替换策略。
  3. MoE-CORE（2026-10）：把“哪些专家常驻内存”和“什么时候传输哪个专家”放在一起协调优化。
  4. FineMoE（EuroSys '26）：细粒度卸载，在延迟和内存占用之间做权衡。

之后这是 2026 年本地 MoE 推理最热的方向。反面证据：一篇 IEEE 分析发现，用现有 SSD 卸载 MoE 权重，每生成一个 token 的能耗可达全放 HBM 的约 12 倍。闪存解决了“放得下”，但付出了能耗和速度的代价，这正是需要新内存架构的原因。

走向：通用卸载 → 利用稀疏性 → 针对 MoE 的专家放置、缓存和预取（2026 年最热）。反面证据：用 SSD 卸载 MoE 权重，每 token 能耗可达 HBM 的约 12 倍

线 ⑤

模型结构变得对本地友好

时间工作之前卡在哪 · 做法 · 之后
2023-12Mixtral 8x7B（Mistral）

之前稠密模型想更强就得更大，每个 token 要读的参数和推理成本一起线性增长：70B 稠密模型每生成一个 token 都要读 70B 参数。

做法
  1. MoE 层：把 Transformer 里的 FFN 换成 8 个并列的“专家”FFN 加一个路由器。路由器看当前 token 的隐藏状态给 8 个专家打分，选最高的 2 个，按分数加权它们的输出。
  2. 注意力层不变：注意力等部分所有 token 共享，只有 FFN 变成专家。
  3. 参数账：总参数约 47B（不是 8 × 7 = 56B，因为注意力等部分是共享的），每个 token 只激活约 13B。

之后质量接近或超过 Llama 2 70B，推理速度接近 13B 模型，Apache 2.0 开源。代价：47B 参数都得放在内存里，“激活少、总量大”从这里开始。

2024-12 / 2025-01DeepSeek-V3 / R1关键

之前开源最强的模型（如 Llama 3.1 405B）是稠密的，训练和推理都极贵，而且和 GPT-4o、Claude 3.5 这类闭源前沿模型仍有差距。

做法
  1. 细粒度 MoE：每层 256 个小专家加 1 个共享专家，每个 token 选 8 个路由专家。专家切得更细，组合更灵活；共享专家负责所有 token 都需要的通用知识。
  2. 无辅助损失的负载均衡：以前要加一个额外的损失项逼路由器平均分配 token，会伤害质量。V3 改成给每个专家的路由分数加一个偏置：某个专家被用得太多，就自动调低它的偏置。
  3. MLA、MTP：MLA 压缩 KV cache（见线 ②），MTP 训练时多预测一个 token（见线 ③）。
  4. FP8 训练：大部分矩阵乘用 FP8 计算，第一次在这个规模上验证可行，大幅降低训练成本。
  5. R1：在 V3 基础上用大规模强化学习训练推理能力（长思维链）。

之后671B 总参数、每个 token 激活 37B；开源模型第一次接近前沿闭源模型。V3 正式训练约 278.8 万 H800 GPU 时，约 560 万美元。对本地推理：每个 token 只读 37B，带宽压力小；但 4 bit 也要约 340GB，问题变成了“放不下”。

2025Qwen3（04）、Kimi K2（07）、gpt-oss（08）

之前DeepSeek 证明了细粒度 MoE 又强又省，其他厂商跟进：激活参数还能更小吗？

做法
  1. Qwen3：235B 总 / 22B 激活；还有 30B 总 / 3B 激活的小版本，在本地机器上非常快。
  2. Kimi K2：1T 总参数、32B 激活，用 MuonClip 优化器让超大规模训练保持稳定。
  3. gpt-oss（OpenAI）：120B 总 / 约 5.1B 激活、20B 总 / 约 3.6B 激活；MoE 专家权重直接以 MXFP4 发布，Apache 2.0。

之后前沿开源模型几乎全是 MoE：总参数越来越大（几百 B 到 1T），每个 token 激活的停在几 B 到几十 B。

2025–26Qwen3-Next、Kimi Linear；DeepSeek-V4、Qwen3.5

之前MoE 解决了“每个 token 读太多”，但长上下文的 KV cache 和全部专家的总容量还在涨。

做法
  1. 混合线性注意力：把 KV 压下来（见线 ② 最后一条）。
  2. 超稀疏 MoE：Qwen3-Next 80B 总 / 约 3B 激活。
  3. 继续演进：DeepSeek-V4、Qwen3.5（2026）沿着这两个方向继续。

之后带宽压力继续下降，容量压力继续上升，这正是“便宜的大容量内存”有市场的原因。

结论：MoE 让瓶颈从带宽转到容量，这是一批做本地推理硬件的公司成立的时间背景
